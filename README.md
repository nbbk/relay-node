# 中转节点一键包（realm 纯转发，线路不好时提速）

**核心：realm**（[zhboner/realm](https://github.com/zhboner/realm)，Rust 写的纯 TCP/UDP 转发，单二进制、内存几 MB、零拷贝）。

> 落地节点看这里：[tiktok-node](https://github.com/nbbk/tiktok-node)（核心：Xray，VLESS + WS + TLS 单协议）｜[sing-box-node](https://github.com/nbbk/sing-box-node)（核心：sing-box，6 协议合一）。中转只转发、不解密、不改协议，落地不用装任何东西。

> 📖 详细教程（安装、卸载、排查运维全流程）：**[TUTORIAL.md](TUTORIAL.md)**

## 相关仓库

- [tiktok-node](https://github.com/nbbk/tiktok-node)：落地节点，Xray 内核，VLESS + WS + TLS 单协议
- [sing-box-node](https://github.com/nbbk/sing-box-node)：落地节点，sing-box 内核，VLESS/Trojan/VMess/Shadowsocks/Hysteria2/TUIC 6 协议合一
- [relay-node](https://github.com/nbbk/relay-node)（本仓库）：中转，realm 纯转发，落地线路不好时提速

## 这是什么

服务器线路不好时，直连落地节点又慢又卡。加一台中转机：

```text
客户端 → 中转机（realm 原样转发）→ 落地机（你现成的节点）
```

中转只做字节转发：TLS 握手仍是客户端和落地机之间端到端完成，UUID、SNI、WS 路径全部不变；域名 A 记录改指到中转机后，**客户端配置一个字都不用改**。

## 为什么这样设计（新手先看这几条）

- **落地填域名，中转填 IP**：证书按域名签，有 TLS 才像普通网站流量；中转和直连都直接用落地 IP，不经过 DNS，也不会因为域名改指后解析错地方。
- **域名分两步指**：先指到落地机（装节点、签证书、验证能用），中转装好验证通过后再改指到中转机 IP；证书还是原来那张，续签照常走转发的 80 端口。改完等几分钟 DNS 生效再测。
- **直连和中转能同时留着**：域名改指后原来那条自动走中转；再加一条直连，地址填落地 IP、SNI 填域名，两条互为备份。
- **中转机端口要空着**：80、443 这些端口要留给 realm 监听，被占了安装脚本会先检查出来；占了也不用换机器，改监听端口就行（只改中转这边，落地端口不变，建议用高位端口，如 443→10443），客户端链接端口跟着改。加第 2 个落地时 80 或 443 被已装好的落地占了，脚本会让你选解决方式：改监听走高位端口（默认，续签手动）、80 按域名分流、443 按 SNI 分流（分流能让几个落地的续签都自动通），见下面“多节点”。
- **双节点怎么来**：安装最后一步粘贴原链接，直接出两条链接和两个二维码；跳过的话事后跑 `bash install.sh --nodes` 补生成。

详细解释见 [TUTORIAL.md](TUTORIAL.md) 开头的“先搞懂为什么”。

## 前置条件

- 一台中转服务器（Ubuntu/Debian，root 权限，x86_64 或 aarch64），离用户近、到落地线路好（香港/新加坡/日本优先）
- 落地服务器上节点已在跑（tiktok-node 或 sing-box-node），记下它的 IP 或域名
- 中转机放行要转发的端口（云厂商安全组 + ufw）

## 使用步骤

### 1. 落地侧先检查（不用装东西）

在落地服务器上跑一条命令，确认节点在跑、打印中转安装要填的信息：

```bash
curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/landing.sh | bash
```

### 2. 中转侧一键安装

在中转服务器上跑一条命令，按提示输入落地 IP 或域名、选预设即可：

```bash
curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/install.sh | bash
```

预设：`1` = tiktok-node（80 + 443）｜`2` = sing-box-node（80 + 443 + 8388 + 8443 + 8444，含 UDP）｜`3` = 自定义端口。装完自动跑 `check.sh` 自检。

> **只想先装面板？不用先装中转**：直接跑下面这条命令只装面板，装完打开面板添加第一个落地，中转会自动装好：
>
> ```bash
> curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/panel-install.sh | bash
> ```

装完最后还会问一句要不要装可视化面板（见下面“可视化面板”），选 `y` 就装好，浏览器里点几下就能管中转；不装也不影响转发。

填写示例（落地是 tiktok-node，落地 IP `203.0.113.1`）：

```text
请填写你的落地 IP 或域名：
① 落地服务器 IP（推荐填 IP，例如 203.0.113.1）或域名，填完按回车：203.0.113.1
② 选预设 [1/2/3]，直接回车选默认 1：1
```

落地是 sing-box-node 就选 `2`（再问 TLS 还是明文：TLS 选 `1`）。

装完最后一步会问你要不要粘贴原节点链接，粘贴后直接给出直连 + 中转两条链接和二维码：

```text
请粘贴你原来的节点链接：
（可多条，一行一条；粘完按一次回车（空行）结束；不想生成就直接回车跳过）
vless://11111111-2222-3333-4444-555555555555@example.com:443?encryption=none&security=tls&type=ws&host=example.com&path=%2Fexample-path#TikTok-Node
（空行回车结束）
```

输出里 `中转：` 是原链接（域名改指后自动走中转），`直连：` 是地址换成落地 IP 并加 `sni=域名` 的版本；两条都存进 `~/relay-node-kit/nodes.txt`，有 qrencode 时还各给一个二维码（终端里直接显示 + 存 PNG）。跳过也没事，装完随时可以只补生成一次：`bash install.sh --nodes`。

### 3. 域名改指（只做一次）

把域名 A 记录从落地 IP 改指到**中转机 IP**，等 DNS 生效后客户端配置一个字都不用改，直接走中转。也可以不改域名、只把客户端地址改成中转 IP（SNI 保持域名不变）。

## 可视化面板

给中转套一个网页面板：浏览器里点几下，完成原来要 SSH 进服务器敲命令做的所有事。面板只改配置、不碰节点流量；面板挂了、关了，都不影响 realm 转发；SSH 加原脚本永远是兜底。

### 安装

- 新装中转时：install.sh 最后一步问“要不要装可视化面板？”，选 `y` 就装好。
- 只装面板（不用先装中转）：直接跑下面这条命令，装完打开面板添加第一个落地，中转会自动装好。
- 已装中转的机器装面板：现有落地自动出现在面板里（面板读同一份 `/etc/realm/relay.conf`），不用重新添加。
- 已装中转的机器：单独跑一条命令：

  ```bash
  curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/panel-install.sh | bash
  ```

- 安装时问账号密码：直接回车用默认（用户名 `admin`、随机强密码），输入自己的就用输入的；装完最后显示一次全部信息（地址、端口、账号、密码）。
- 忘了地址或密码：SSH 上服务器跑一条短命令就能重新看到：

  ```bash
  panel-info
  ```

- 升级：重跑安装命令，账号密码与配置保留；面板里也有“检查更新”按钮。更新面板时只重启面板自己，不动 realm，正在用的节点不断线。
- 卸载：`bash panel-install.sh --remove`；`bash stop.sh --remove` 删中转时也会问要不要一起删面板。

### 面板里能做什么

- **总览**：realm 运行状态、每个落地的在线状态、延迟、证书剩余天数；一键体检（相当于跑 `check.sh`），体检出问题旁边直接给修复按钮。
- **添加落地**：填表提交；端口冲突时自动弹出方式选择（改监听走高位端口 / 80 分流 / 443 分流，各带详细解释），和脚本里一样。提交后显示新节点链接加二维码。
- **落地管理**：查看链接/二维码、切换分流方式、给落地加节点、续期、删除。删除是软删除，进回收站保留 7 天、一键恢复。
- **给落地加节点**：面板在中转机上，够不着落地机，所以做成向导式——面板里填个新子域名，生成落地机上要跑的命令（复制），到落地机上跑完，把新节点链接粘贴回面板登记；同一台落地机的多个节点共用中转的一条 443 转发，不用再加中转规则。
- **节点链接**：粘贴原链接，生成直连加中转 twin 加二维码；历史记录就是 `nodes.txt` 的内容。
- **证书**：每个域名证书剩余天数，不到 30 天变黄、不到 7 天变红；手动续签有六步引导，每步带按钮和命令复制。
- **流量**：每个落地当日、本月、累计上下行流量，带图表。流量限制两种算法：总量（整个节点生命周期内，如 100GB，用完即停）和按月（每月重置）；与到期时间是“或”的关系，哪个先到节点就停用，面板会写明停用原因；续期只延长时限、续量只补流量。分节点统计第一版不做（同一台落地机多个节点共用一条转发，分不开），先做按落地的统计。
- **节点到期**：添加时可选 30/90/180/365 天、自定义天数或永久（默认永久）；到期前 7 天和 3 天提醒，到期自动停用，一键续期恢复。节点到期和证书到期是两回事，面板里分开显示。
- **端口管理**：指定开放、范围开放、一键开放全部端口（二次确认 + 风险提示）；只管本机防火墙（ufw），云厂商安全组还得去控制台开。
- **服务与日志**：启动、停止、重启 realm；实时日志；端口占用表。
- **设置**：面板端口、改密码、IP 白名单、HTTPS 开关、检查更新、重启面板。
- **备份恢复**：每次改配置前自动备份（保留最近 10 份），面板里一键恢复；一键导出/导入整机配置，换中转机时导入就全回来了。
- **Telegram 提醒**：证书快到期、中转挂了、落地到期、流量到 80%/100% 时自动发消息；需要提供 Bot Token 和 Chat ID，设置一次就行，不用就只在面板里标红。

### 访问与 HTTPS

- 装完直接用 IP 加端口打开面板，默认端口 `11111`，例如 `http://203.0.113.1:11111`。
- HTTPS 在安装时或面板设置里一键开启，面板自动完成证书，不用再做别的操作。用 IP 访问时是自签证书（浏览器首次提示一次，点继续访问即可，之后全程加密）；给面板绑了域名则自动申请 Let's Encrypt 真证书（走 DNS 验证，不占 80 端口），浏览器没有警告。绑域名开 HTTPS 要先在设置里填 Cloudflare API 令牌（只用 IP 访问不要令牌）；令牌怎么开见 [CLOUDFLARE_TOKEN.md](CLOUDFLARE_TOKEN.md)。
- 安全：登录失败限流（5 次失败锁 5 分钟）、可选 IP 白名单、所有输入服务端二次校验；面板以 root 运行（必须改 `/etc/realm`、管 systemd），代码开源可审。

## 多节点（一台中转机转多个落地）

一台中转机可以转多个落地节点，不用一台机器只转一个：

- 装完第 1 个落地后脚本会问“还要再加一个落地节点吗？”，选 `y` 就接着加；事后想加随时跑 `bash install.sh --add`（不覆盖已有配置，直接往后加）。
- 追加时 BBR、systemd 服务、realm 二进制都只建一次；新落地只往配置里追加转发规则，改完自动重启生效。
- **监听端口不能撞**：两个落地都走 443 时，第二个的监听端口必须改（只改中转这边，落地端口不变）。加第 2 个及以上落地、80 或 443 被已装好的落地占了时，脚本会停下来让你选一种解决方式（只影响新加的这个落地，已经装好的不动；直接回车就是默认 1）：

  | 方式 | 是干什么的 | 适合谁 / 要什么 | 代价 |
  |---|---|---|---|
  | **1）改监听走高位端口**（默认） | 新落地的监听端口改成高位端口，如 443→10443，realm 继续纯转发 | 最简单，什么都不用准备，装完就能用 | 客户端链接要带高位端口；第 2 个及以后的落地证书续签要手动（见下面“手动续签证书”） |
  | **2）80 按域名分流** | 中转机上跑一个轻量代理（nginx）监听 80，按域名把证书验证请求分到对应落地的 80；realm 继续转 443，各走各的高位端口 | 几个落地的证书续签都自动通，不用令牌、落地不用改 | 中转 80 不再是纯转发、多一个代理组件；443 还是各走各的高位端口 |
  | **3）443 按 SNI 分流** | 中转机按 TLS 握手里的域名分流（HAProxy，纯透传不解密），几个落地共用中转的 443；证书续签走 443（TLS-ALPN-01）自动通 | 客户端链接不用带高位端口，效果最彻底 | 改动最大：中转 443 不再是 realm 纯转发，要多装一个分流组件 |
  | **4）80 分流 + 443 分流一起用** | 2 和 3 一起：80 和 443 都能共用 | 几个落地续签都自动通，客户端链接也不用带高位端口 | 中转机上要多两个分流组件，80 和 443 都不再是 realm 纯转发 |

  只 80 冲突时只给 1/2 选，只 443 冲突时只给 1/3 选，两个都冲突时 1/2/3/4 都能选。选了分流后，再加落地直接加入分流、不再问；分流组件装不上或起不来时自动回退到方式 1。443 分流选 HAProxy 而不是 nginx stream / sniproxy / Caddy layer4：单个 apt 包就能装、专为 L4 设计、纯透传不解密，TLS-ALPN-01 能原样穿过；sniproxy 上游已废弃、Caddy layer4 要自定义编译太重。
- **客户端链接端口跟着监听端口改**：第 7 步生成的中转链接会自动把端口换成实际监听端口（直连那条保持落地端口不变）；两条链接按落地分组存在 `~/relay-node-kit/nodes.txt`。选了 443 SNI 分流的落地，中转链接不用带高位端口、就是原来的 443。
- `bash check.sh` 会把每个落地都验一遍（监听端口 + TLS 证书指纹 + 各落地证书剩余天数）；`bash stop.sh` 停的是全部落地。

## 任意门模式（节点域名永远不用改指向）

标准模式要改两次域名指向（先指落地签证书、再改指中转），第 2 个及以后的落地证书续签还走不通中转。任意门模式把这个麻烦去掉：

- **节点域名永远指着落地不动**：证书签发和续签都在落地直连完成，中转完全不碰。
- **中转机上每个落地分一个专用转发端口**：转发端口 = 落地端口 + 20000（443→20443、80→20080、8388→28388、8443→28443、8444→28444）；+20000 超出范围时自动退到 +10000、再退 +1000。
- **链接用“中转地址:转发端口”**：SNI 还是节点域名，TLS 仍是客户端和落地端到端直通，中转只转发字节。
- **中转地址**：安装时问一次，默认自动探测本机公网 IP（直接回车就是它），也可以直接填域名；面板设置里随时能改，改完历史记录里的任意门链接跟着变。

| | 标准模式 | 任意门模式 |
|---|---|---|
| 节点域名指向 | 改指中转机 | 永远指落地，不用动 |
| 客户端链接 | 节点域名:443，不带端口 | 中转地址:转发端口，如 `203.0.113.1:20443` |
| 证书续签 | 第 1 个自动；第 2 个及以后要手动或分流 | 全部自动（走落地直连） |
| 中转地址暴露 | 不暴露（链接里只有节点域名） | 暴露在链接里 |
| 防火墙 | 只放行 80/443 | 每个转发端口都要放行 |
| 适合 | 域名能自由改指向、只转一两个落地 | 不想改来改去域名指向、要转多个落地、域名动不了 |

**怎么用**：安装时在“转发模式”那一步选 2（任意门模式），后面照常选预设；装完第 7 步只出“任意门 + 直连”两条链接和二维码（标准模式的“中转”链接在任意门模式下没有意义：节点域名指着落地，那个端口上什么都没有）。追加落地：`bash install.sh --add`，同样先选模式；转发端口冲突时可自填覆盖（格式“落地端口:转发端口”，如 `443:30443`）。事后补生成：`bash install.sh --nodes`。单条生成：`bash install.sh --door '<链接>' <中转地址> <转发端口> [sni域名]`（面板调用）。

**防火墙注意**：转发端口要在**云厂商安全组**和**中转机 ufw** 里都放行（TCP 和 UDP 各放各的，HY2/TUIC 的 UDP 别漏）。只放了 TCP、没放 UDP，SS/HY2/TUIC 会不通。

**和 DNS 验证的关系**：任意门治的是“转发方式”（不用改指向），DNS 验证（见 `XBOARD_DNS01.md` / `CLOUDFLARE_TOKEN.md`）治的是“证书续签”（不用 80 验证）。两个可以一起用，也可以只用一个：任意门模式下域名本来就指着落地，续签已经自动通了，DNS 验证不是必须的。

## 手动续签证书

证书一般 90 天到期，到期没续上节点就不通了。`bash check.sh` 第 5 节会显示每个落地的证书剩余天数，不用自己记日子。

**谁需要手动续签，谁不用：**

- **需要**：选了方式 1（改监听走高位端口）的**第 2 个及以后落地**。它的 80 不再走中转转发，Caddy 的证书验证请求到不了落地，自动续签走不通。
- **不用**：第 1 个落地（走中转 80 自动续）；选了 80 按域名分流或 443 按 SNI 分流的落地（续签自动通）；**任意门模式的落地**（域名指落地，续签走落地直连，见上面“任意门模式”）。

**时间窗口**：Caddy 只在证书到期前 30 天内才开始续，别太早操作，建议**到期前 2 周内**做。check.sh 剩余天数 <30 天报 `[注意]`、<7 天或已过期报 `[风险]`，看到 `[注意]` 再动手。

**具体步骤**（以第 2 个落地、域名 `example.com`、落地 IP `203.0.113.1` 为例）：

1. 用 check.sh 看各落地证书剩余天数，确认是哪个落地要续：
   ```bash
   bash check.sh
   ```
2. 把该落地的域名 A 记录改回指向落地机 IP（Cloudflare DNS 里改）：`example.com` 的 A 记录从中转机 IP 改回 `203.0.113.1`。
3. 等 DNS 生效（TTL 一般 5 分钟），核对返回的是落地 IP：
   ```bash
   dig example.com +short
   # 应返回 203.0.113.1
   ```
4. 重启落地 Caddy 触发续签（在落地机上跑，tiktok-node 和 sing-box-node 的容器名不一样）：
   ```bash
   # tiktok-node（落地机）：
   cd ~/tiktok-node-kit && docker compose restart caddy
   # 或：docker restart tiktok-caddy

   # sing-box-node（落地机）：
   cd ~/sing-box-node-kit && docker compose restart caddy
   # 或：docker restart singbox-caddy
   ```
5. 核对新到期日（剩余天数应回到 90 天左右）：
   ```bash
   bash check.sh
   # 第 5 节看该落地的剩余天数
   ```
6. 把域名 A 记录改回指向中转机 IP，等 DNS 生效后再跑一遍 `bash check.sh`，确认中转正常。

## 防 DNS 泄露

中转不产生、不改写客户端的任何 DNS 请求（纯字节转发）；防泄漏仍由落地节点（DoH）和客户端配置负责。中转只在启动时解析一次落地域名，填落地 IP 可完全跳过 DNS；解析走 TCP + 公共 DNS（1.1.1.1/8.8.8.8），不走明文 UDP 53。

## 速度

- realm 零拷贝转发（splice，内建）+ 中转机开 BBR + fq + 大 TCP 缓冲
- 中转多一跳，但两段好线路能换掉一段烂直连；中转机选址是关键：离用户近、到落地线路好
- 中转后反而更慢 = 中转到落地那段线路差，换一台中转机（排查见 [TUTORIAL.md](TUTORIAL.md)）

## 停止 / 删除中转

```bash
bash stop.sh            # 停止中转，保留配置
bash stop.sh --remove   # 彻底删除（realm 二进制、配置、服务、sysctl、目录全删）
```

再启动的命令就是下面这条（只针对 `bash stop.sh` 保留配置的情况，跑完中转按原配置重新起来）：

```bash
systemctl start realm
# 查是不是起来了：
systemctl status realm
```

远程一键停：`curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/stop.sh | bash`（`--remove` 用 `| bash -s -- --remove`）。删完记得把域名 A 记录改回指向落地 IP。`--remove` 时会问要不要把可视化面板一起删掉（只删面板服务、二进制和数据，中转的删除不受影响）。

## 常见问题

- **证书报错 / 浏览器报不安全**：多半是域名还没指到中转机，或 DNS 还没生效；`bash check.sh` 会核对经中转的证书指纹与落地是否一致
- **UDP 不通（HY2/TUIC/SS 连不上，但 VLESS 能连）**：先查云厂商安全组有没有放行对应 UDP 端口（TCP 放了不等于 UDP 放了）
- **中转后更慢**：中转到落地那段线路差，换中转机；不要只看一跳的延迟
- **多落地 / 故障转移**：一台中转机可以转多个落地（见上面“多节点”），`bash install.sh --add` 追加；想让客户端在两个中转之间自动切换，realm 本身不做客户端选路，靠客户端自己换节点

详细排查见 **[TUTORIAL.md](TUTORIAL.md)**。
