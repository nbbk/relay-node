# 中转节点一键包（relay-node，realm 纯转发）

**定位：** 落地线路不好时，加一台中转机提速。中转只做字节转发，不解密、不改协议。

```text
客户端 → 中转机（realm 原样转发）→ 落地机（你现成的节点）
```

TLS 握手仍是客户端和落地机之间端到端完成，UUID、SNI、WS 路径全部不变；域名 A 记录改指到中转机后，**客户端配置一个字都不用改**。

## 相关仓库

- [relay-node](https://github.com/nbbk/relay-node)（本仓库）：中转，realm 纯转发，落地线路不好时提速。
- [landing-node](https://github.com/nbbk/landing-node)：落地节点，安装第一步先选核心——Xray（VLESS + WS + TLS 单协议）或 sing-box（VLESS/Trojan/VMess/Shadowsocks/Hysteria2/TUIC，6 协议合一）。
- 旧仓说明：旧的 tiktok-node 与 sing-box-node 两个落地仓库已合并为 landing-node，旧仓只剩一个转发垫片，旧一键命令仍能跑、会自动指到新仓；新装落地一律用 landing-node。

## 一键命令

下面三条命令各管一件事，不要混着用。

**先在落地机上跑检查命令，确认节点在跑、拿到中转安装要填的信息：**

```bash
curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/landing.sh | bash
```

**再在中转机上跑安装命令，按提示填落地 IP、选预设即可：**

```bash
curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/install.sh | bash
```

**只想先装可视化面板、不用先装中转，跑面板安装命令：**

```bash
curl -fsSL https://raw.githubusercontent.com/nbbk/relay-node/main/panel-install.sh | bash
```

装完面板，打开面板添加第一个落地，中转会自动装好。

## 填什么：三个提示，每个都有默认值

安装时脚本会逐个问你，每问一个都有带冒号的提示行，直接回车就是默认值。

**提示：请填写你的落地 IP 或域名：**

- 填落地服务器的 IP，推荐填 IP，例如 `203.0.113.1`；也可以填域名。
- 为什么推荐填 IP：转发和直连都直接用这个 IP，不经过 DNS，也不会因为域名改指后解析错地方。

**提示：选哪种模式？[1/2]，直接回车选默认 1（标准模式）：**

- 选项 1 是标准模式：域名 A 记录指到中转机，客户端用节点域名直连中转的 80/443，链接干净、不用带端口。适合域名能自由改指向、只转一两个落地。
- 选项 2 是任意门模式：节点域名永远指着落地不动，中转机上每个落地分一个专用转发端口，客户端用“中转地址:转发端口”连过来。适合不想改来改去域名指向、要转多个落地、或域名动不了。代价是链接要带转发端口，中转地址会暴露在链接里。

**提示：选预设 [1/2/3]，直接回车选默认 1：**

- 选项 1 是 landing-node（Xray 核心）：转发 80 + 443（TCP）。适合落地是 Xray 核心。
- 选项 2 是 landing-node（sing-box 核心）：TLS 模式转发 80 + 443（TCP）+ 8388（TCP+UDP）+ 8443（UDP）+ 8444（UDP）；明文模式转发 8080–8082 + 8388。适合落地是 sing-box 核心，选完再问 TLS 还是明文，直接回车就是 TLS。
- 选项 3 是自定义端口：自己输端口，逗号分隔；监听端口默认与落地端口相同，如需改监听端口用 `监听:落地` 的写法，例如 `443,8388,8443:9443`。

装完脚本自动跑一遍自检，最后会问你要不要粘贴原节点链接，粘贴后直接给出中转 + 直连两条链接和二维码，存进 `~/relay-node-kit/nodes.txt`。

## 域名改指（只做一次）

先把域名 A 记录指到落地机、装节点、签证书、验证能用；中转装好验证通过后，再把 A 记录改指到**中转机 IP**，等 DNS 生效后客户端配置一个字都不用改，直接走中转。也可以不改域名、只把客户端地址改成中转 IP（SNI 保持域名不变）。

## 架构

- **中转机：** 跑 realm（Rust 写的纯 TCP/UDP 转发，单二进制、内存几 MB、零拷贝），配 BBR + fq + 大 TCP 缓冲；另可选装可视化面板（浏览器里管中转，面板挂了不影响转发）。
- **落地机：** 跑 landing-node（Xray 或 sing-box 核心），不用为中转装任何东西；证书签发和续签仍由落地负责。
- **分工：** 中转只解决路由和 IP 暴露，不改变协议伪装；防 DNS 泄露仍由落地节点和客户端配置负责。
- **多落地：** 一台中转机可以转多个落地，装完跑 `bash install.sh --add` 追加；两个落地都走 443 时，第二个要改监听走高位端口，或走 80 按域名分流、443 按 SNI 分流。
- **面板两种模式：** 完整面板（中转 + 面板在同一台机器上，默认）与管理面板（单独一台机器只做集中管理，不管本机中转）。

## 常用命令

**查看中转是不是在跑，跑下面这条查看服务状态的命令：**

```bash
systemctl status realm --no-pager
```

**跑一遍自检，核对监听端口、证书指纹与剩余天数，跑下面这条命令：**

```bash
bash check.sh
```

**停止中转、保留配置（以后还能再启动），跑下面这条停止命令：**

```bash
bash stop.sh
```

**彻底删除中转（配置、服务、二进制全删），跑下面这条删除命令：**

```bash
bash stop.sh --remove
```

**停止后想再启动中转（只针对上面 `bash stop.sh` 保留配置的情况），跑下面这条启动命令：**

```bash
systemctl start realm
```

**改了配置要生效，不用停了再起，跑下面这条重启命令（重启就是先停再起一次完成）：**

```bash
systemctl restart realm
```

注意区分：`status` 只是查看状态，不动服务；`start` 是把停掉的服务再启动起来；`restart` 是把正在跑的服务停了再起一次；`stop.sh` 是停中转并保留配置；`stop.sh --remove` 是彻底删除。删完记得把域名 A 记录改回指向落地 IP。

## 可视化面板（面板版本 1.3.29）

面板是给中转套的一个网页面板：浏览器里点几下，完成原来要 SSH 进服务器敲命令做的所有事。

- **安装：** 新装中转时 install.sh 最后一步问“要不要装可视化面板？”，直接回车就是默认 N（不装），输入 `y` 就装好；已装中转的机器单独跑 panel-install.sh；只装面板不用先装中转，装完打开面板添加第一个落地，中转会自动装好。
- **登录：** 安装时问账号密码，直接回车用默认（用户名 `admin`、随机强密码），输入自己的就用输入的；装完最后显示一次全部信息（地址、端口、账号、密码），只显示一次，记下来。
- **访问：** 装完直接用 IP 加端口打开面板，默认端口 `11111`，例如 `http://203.0.113.1:11111`。
- **忘了地址或密码：** SSH 上服务器，跑下面这条找回信息的命令，就能重新看到地址、账号和密码：

```bash
panel-info
```

- **面板里能做什么：** 总览与一键体检、添加与管理落地、节点链接生成、证书与续签、流量与限流、订阅链接（一人一条、合并订阅、分组）、集中管理多台面板、备份与整机迁移恢复、Telegram 提醒、机器监控与延迟探测。详细按页讲，见 [relay-TUTORIAL.md](relay-TUTORIAL.md) 第 2 节。
- **更新：** 面板里点“检查更新”或重跑 panel-install.sh；更新面板时只重启面板自己，不动 realm，正在用的节点不断线。
- **卸载面板：** 跑 `bash panel-install.sh --remove`；删中转时 `bash stop.sh --remove` 也会问要不要一起删面板。

## 常见问题

- **证书报错 / 浏览器报不安全：** 多半是域名还没指到中转机，或 DNS 还没生效；跑 `bash check.sh`，它会核对经中转的证书指纹与落地是否一致。
- **UDP 不通（HY2/TUIC/SS 连不上，但 VLESS 能连）：** 先查云厂商安全组有没有放行对应 UDP 端口，TCP 放了不等于 UDP 放了。
- **中转后更慢：** 中转到落地那段线路差，换一台中转机；不要只看一跳的延迟。
- **多落地 / 故障转移：** 一台中转机可以转多个落地，跑 `bash install.sh --add` 追加；realm 本身不做客户端选路，想让客户端在两个中转之间自动切换，靠客户端自己换节点。

详细排查见 **[relay-TUTORIAL.md](relay-TUTORIAL.md)** 第 4 节。
